# 다음 작업과 재개 지점

기준일: 2026-10-05. 다음 주 재개용 작업표다. 후속 계획이며 골든패스에 새 기준을 추가하는 문서가 아니다.

## 2026-10-08 추가: 신규 모델 도입 전 공통 작업 관리

작업 목록은 파일·n8n AI·문서 색인·임베딩·검색·Raya 직접 호출의 이력을 통합한다. 사용량·임베딩·RAG 전용 화면은 유지하고 모든 구현 서비스를 공통 서비스 목록에 등록한다. 직접 호출은 기존 응답을 유지하며 실행 이력과 보관 기한이 있는 요약을 남긴다.

다음 단계는 실행 경로의 통합이다. 초기 전체 연산 동시 실행 수 1은 사용자가 선택한 현재 설계안이며 골든패스 기준으로 추가하지 않는다. 기존 워커·워크플로·직접 호출이 같은 자원 배정을 거치도록 하고, n8n이 다시 호출하는 Raya·검색 단계를 별도 Job 대기로 막아 부모 작업과 교착시키지 않도록 처리한다. 실제 실행 종료·자원 반환·재시작·취소를 확인한 뒤 다음 작업으로 넘어가는 동작을 검증한다. 이 단계 후 STT·자막·번역·OCR·TTS를 순차 추가한다.

| 영역 | 구현 상태 |

| 웹 | 작업·단계·결과·플랫폼 알림 상태·사용자 승인·연동 지침 |
| 플랫폼 계약 | 전용 키 API·개별 조회·서명 웹훅·최대 8회 전송·결과 저장 확인 |

코드 검증은 자동 테스트 64개 통과, 웹 동작 검사, 외부 문서·인증·서비스 상태 확인까지다. 실제 플랫폼 등록·뷰어·5GiB 전송·실기기 코덱 대조는 미완료다. 수신 URL 미설정으로 플랫폼 신규 접수는 현재 비활성 상태다.

## 다음 주: 플랫폼 연결과 전환

아래 1~9번을 먼저 진행하고 AI 서비스 확장으로 넘어간다.

| 순서 | 작업 | 작업 위치 | 완료 판단 |
|---|---|---|---|
| 1 | 전용 키 주입·프록시 설정 | 플랫폼·외부 NPM | NOEDAERI_PLATFORM_API_KEY·NOEDAERI_PLATFORM_WEBHOOK_SECRET을 플랫폼 비밀 설정에 주입. 원본 첨부 저장 한도·외부 프록시를 5GiB에 맞추고 제한시간 확인 |
| 2 | HTTPS 완료 웹훅 수신기 | 플랫폼 | 원문 body HMAC·시각·이벤트 ID 검증. event_id UNIQUE인 영속 inbox에 기록한 뒤 빠르게 2xx 응답. 결과 다운로드는 별도 작업으로 실행 |
| 3 | 작업 접수·원본 전송 | 플랫폼 | file ID·현재 generation·요청 UUID·뇌대리 job ID를 DB에 연결. 동일 접수 재전송은 같은 키·내용 유지. 업로드 응답 유실은 개별 조회로 복구 |
| 4 | 결과 수령·실패 복구 | 플랫폼 | 다운로드 실패의 제한 재시도·부분 파일 정리. ZIP 파일명·경로·해제 크기 검사. 영구 저장 실패 시 receipt를 보내지 않음 |
| 5 | 파생물 등록·오래된 결과 차단 | 플랫폼 | 등록 트랜잭션에서 원본 존재·삭제 상태·현재 generation·job ID 대조. 삭제된 파일과 이전 변환 결과의 반영 차단. 중복 알림도 한 번만 반영 |
| 6 | 기존 뷰어·화면 갱신 | 플랫폼 | 이미지 썸네일·미리보기, HLS 상대 이름·공개 경로 연결. 480/720/1080 수용. 알림 수신·등록 완료 후 화면 갱신. 완료 대기용 반복 폴링을 사용하지 않음 |
| 7 | 저장 확인·수신 URL 설정 | 양쪽 | 영구 저장·파생물 등록 커밋 후 receipt. 플랫폼 수신 HTTPS 주소를 뇌대리 암호화 설정에 넣고 재시작. 키·서명·경로의 실제 연결 확인 |
| 8 | 실제 파일·장애 검수 | 양쪽 | 아래 검수표의 결과 기록. 기존 플랫폼 결과·뷰어와 대조. 공간을 확보해 실제 5GiB 전송 검수 |
| 9 | 단계적 운영 전환 | 플랫폼 | 기능 플래그로 이미지부터, 이어서 영상 전환. 실패 시 기존 처리로 되돌릴 경로 확인. 안정성을 확인한 뒤 기존 연산 경로 정리 |

플랫폼 원본 저장·권한·Range·원본 보기·PDF/TXT/Markdown/오디오 원본 뷰어·OG·공유 URL은 플랫폼에서 유지하는 현재 연결 범위다.

### 실제 연결 검수표

| 검수 | 확인할 결과 |
|---|---|
| 이미지 | 모바일 HEIC/HEIF·AVIF·EXIF 회전·투명도·ICC·첫 프레임·손상 입력 |
| 영상 | 가로·세로·회전·무음·각 화질·작은 영상·입력 코덱·긴 영상·큰 파일 |
| 스트리밍 | master·화질 재생 목록·모든 조각의 등록, 상대 경로 재작성, PC·모바일 재생·화질 전환 |
| 전송 | 실제 5GiB, 연결 끊김, 접수·업로드 응답 유실, 다운로드 실패와 재다운로드 |
| 중복·역순 | 같은 알림 여러 번, 이전 작업 알림의 늦은 도착, 파일 삭제 직전·직후 완료 |
| 장애 | 수신 서버 중단, 전송 소진·수동 재전송, 워커 종료·재시작·점유 만료, 디스크 부족 |
| 보존 | 저장 확인 전 유지·확인 후 다운로드 차단 및 실제 정리·자연 만료·정리 실패 |
| 접근 | 잘못된 키·철회된 사용자·다른 소유자·비관리자의 플랫폼 작업 접근 차단 |

알림 수신만으로 저장 완료를 확인하지 않는다. 삭제·세대 변경으로 결과를 버릴 때도 영구 저장했다고 잘못 보고하지 않는다. 현재는 진행 작업 취소와 보관 상한을 사용하며, 폐기 확인 API가 필요해지면 그때 계약을 추가한다.
