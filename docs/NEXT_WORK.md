## 2026-10-09 현재 재개 지점 · n8n 연결 검수

n8n·플랫폼 접속이 복구되어 뇌대리 → 실제 n8n 태그 생성과 빈 컬렉션 RAG → Raya →
답변 반환을 검수했다. 실제 활성 웹훅 담당 워크플로를 암호화 설정에 연결하고, 서버의
분기·모델·프롬프트·자격증명을 보존해 두 내부 HTTP 헤더와 토큰 분리를 반영했다.
n8n 실행 데이터 저장을 끄고, n8n 본문의 실패를 뇌대리 성공으로 기록하지 않도록 보완했다.

플랫폼의 환경 확인·issuer·프로젝트/환경 대조는 성공했다. 현재 키는 AI 권한이 없어
AI 조회가 403이다. 사용자 결정에 따라 **뇌대리 작업물 검토 → 플랫폼 어댑터 반영 →
필요한 AI 권한 키 발급 → 실제 연결 검수** 순서로 진행한다. 기존 플랫폼 키는 유지했다.
플랫폼 AI 실행·파일 결과 등록·완료 웹훅까지 검수한 상태로 해석하지 않는다.

다음 구현 순서는 STT → OCR → 영상 자막 → 문장 번역이다. Docker를 도입하지 않는다.
Docker 레지스트리 복구 여부는 별도로 확인하지 않았고 이 작업에는 사용하지 않았다.
실제 사용자 녹음 품질·재부팅/NAS 단절·실서비스 동시 파일/TTS·취소·타임아웃은 남아 있다.

### 이전 기록: 서버 점검 중 로컬 준비

n8n·플랫폼·Docker 레지스트리에 접근할 수 없다는 사용자 제약으로 네이티브 로컬 개발과
모의 응답 검사만 진행한다. 실제 서버 계약은 기존 문서와 코드로 확인하고 새 서버 구현을 추측하지 않는다.
Docker 이미지·레지스트리·원격 워크플로 배포를 사용하지 않는다.

공통 자원 배정은 파일·TTS·Raya·임베딩·검색·색인·n8n 워크플로에 연결했다.
최상위 연산 1개와 n8n 자식 단계 1개를 구분하며, 자식은 해당 부모의 실행 토큰을 이어받는다.
작업/자원 대기·불확실한 실행·관리자 종료 확인 화면과 오프라인 n8n export 변환 스크립트를 추가했다.
Raya API는 공통 모드에서 매 작업 종료 후 해제하며 저장된 유지/유휴 정책은 사용하지 않는다.

아래 내용은 복구 전 준비 기록이다. 최신 n8n export의 내부 HTTP 헤더를 반영·검수한 뒤 암호화 설정의
`N8N_COMPUTE_CONTEXT_READY=1`을 적용해야 한다. 기본 0은 서버 호출을 차단한다.
플랫폼의 요청자별 목소리 선택·결과 저장·실제 웹훅 검수도 복구 후 진행한다.
실제 사용자 녹음 품질 검수와 실제 재부팅/NAS 단절 검수는 아직 남아 있다.
다음 로컬 구현 순서는 STT → OCR → 영상 자막 → 문장 번역이다.

아래 2026-10-05/08 작업표도 이전 기준 기록이다. 수신 URL 미설정·n8n 키만 보관이라는

## 2026-10-08 추가: 신규 모델 도입 전 공통 작업 관리

작업 목록은 파일·n8n AI·문서 색인·임베딩·검색·Raya 직접 호출의 이력을 통합한다. 사용량·임베딩·RAG 전용 화면은 유지하고 모든 구현 서비스를 공통 서비스 목록에 등록한다. 직접 호출은 기존 응답을 유지하며 실행 이력과 보관 기한이 있는 요약을 남긴다.

다음 단계는 실행 경로의 통합이다. 초기 전체 연산 동시 실행 수 1은 사용자가 선택한 현재 설계안이며 골든패스 기준으로 추가하지 않는다. 기존 워커·워크플로·직접 호출이 같은 자원 배정을 거치도록 하고, n8n이 다시 호출하는 Raya·검색 단계를 별도 Job 대기로 막아 부모 작업과 교착시키지 않도록 처리한다. 실제 실행 종료·자원 반환·재시작·취소를 확인한 뒤 다음 작업으로 넘어가는 동작을 검증한다. TTS는 파일 워커와 공유하는 로컬 슬롯에 먼저 추가했다. 이후 공통 예약 연결 상태는 위 2026-10-09 기록을 따른다.

Qwen3-TTS 1.7B CustomVoice·Base 8bit를 별도 MLX 환경에 설치했다. 기본 목소리와 참조 음성
등록·목소리 이름 수정/삭제·선택 프로필 합성·웹 오디오·통합 작업 조회를 구현했다.
참조 음성은 영속 저장, 웹 합성 결과는 완료 후 24시간 보관으로 구분한다.
파일·TTS의 로컬 실행 슬롯은 1개이며 모델은 작업 종료 시 해제한다.
목소리는 요청자 ID·프로젝트·환경으로 구분하고 참조 파일은 공통 NAS 루트의
`tts/voices/<voice_id>/reference.wav`에 보관한다. 향후 다른 서비스도 전용 폴더를 사용한다.
목소리 미지정·미등록·삭제 시 내장 기본 목소리 Sohee로 합성하며 웹에서도 등록 없이 테스트할 수 있다.
존재하는 다른 요청자의 목소리나 미완료·유실된 참조 음성은 기존 오류를 유지한다.
NAS 루트·접속 정보는 암호화 env에만 저장했다. 로그인 후 실행하는 연결 관리자는 30초마다
확인·재연결한다. 실제 NetFS 호출·NAS 쓰기/읽기/삭제·자동 시작 설정·운영 TTS API를 확인했으며
실제 재부팅·NAS 연결 단절 후 복구는 미검수다.

통합 검사 137개 통과·5개 생략. 별도 실제 MLX 검사에서 등록 없는 기본 목소리와
CustomVoice/Base 합성·워커 실행을 확인했다.
TTS·통합 작업·이미지·영상 웹 동작 검사와 린트·빌드를 실행했다. 실제 사용자 녹음의
음질은 아직 검수하지 않았다.

다음 우선순위는 전체 실행 경로의 자원 예약 통합, 실제 사용자 녹음으로 음질·속도 검수,
플랫폼의 요청자별 기본 목소리 매핑과 결과 저장 연결이다. 이어 STT, OCR, 영상 자막,
번역을 하나씩 추가한다. n8n은 여러 단계나 후속 처리를 연결할 필요가 있을 때 사용한다.
단순 로컬 추론에는 불필요한 n8n 경유를 추가하지 않는다.
