# PDF 추출 실행 기록

기준일: 2026-10-10. macOS PDFKit + 기존 Apple Vision revision 3을 네이티브 실행한다.
Docker·새 모델·새 상시 프로세스·n8n 단계는 추가하지 않는다.

## 설치와 설정

`python3 scripts/install_ocr.py`로 PDFKit이 포함된 새 Swift 소스를 재빌드한다.
기존 OCR 매니페스트의 소스·실행 파일 SHA-256을 검증하며 `OCR_ENABLED=1`이 필요하다.

암호화 env의 `PDF_MAX_INPUT_BYTES` 기본 200,000,000바이트(공통 업로드와 작은 값),
`PDF_MAX_PAGES` 기본 100, `PDF_TIMEOUT_SECONDS` 기본 900초를 적용한다.
각 범위는 1바이트–5GiB, 1–500페이지, 30–7,200초다. API·워커 재시작 후
서비스 목록의 `pdf.extract.available`·`pdf_limits`로 확인한다.

## 처리와 보존

`auto`는 페이지의 내장 텍스트가 있으면 추출하고 없으면 Vision OCR로 처리한다.
혼합 페이지의 이미지 속 문자를 빠짐없이 추출하는 보장은 없다. `ocr`는 모든 페이지 OCR,
`text`는 내장 텍스트만 추출한다. 빈 페이지는 성공·빈 텍스트다.
한 페이지씩 최대 144dpi·4,096px로 렌더링하며 완료 페이지 수만 진행 상태로 보고한다.
표·서식·다단 읽기 순서 복원과 암호 입력은 제공하지 않는다. 암호화/잠금 PDF는 거부한다.

공통 Job·연산 슬롯·취소·점유 갱신·완료 웹훅·수령 확인을 사용한다. 결과는
`document.txt`·페이지별 `document.json`·ZIP이며 전체 텍스트는 DB 이력·로그·웹훅에 넣지 않는다.
JSON 4MiB·전체 OCR 10,000줄과 전체 시간 제한을 적용한다. 파일 결과에 16MiB를 예약한다.
원본은 기존 작업 정리, 요청·진행 파일은 finally 정리한다. 페이지 이미지는 영구 저장하지 않는다.
웹 결과 24시간, 플랫폼 결과는 receipt 또는 기본 최대 7일, 작업 이력은 유지한다.
별도 영속 PDF 데이터는 없으며 향후 필요 시 공통 NAS의 서비스/용도별 보관 기준을 따른다.

## 검수 범위

전체 검사 172개 통과·5개 건너뜀(TTS MLX 3·VideoToolbox 2).
실제 PDFKit/Vision으로 2페이지 텍스트+스캔 PDF의 자동 분기, 텍스트 전용·전체 OCR,
회전 페이지, 암호화 거부, 페이지 초과·취소·시간 제한·잘못된 헤더와 임시 파일 정리를 확인했다.
API에서는 서비스 등록·승인 접근·공통 작업 조회·업로드 한도/재전송·결과 파일 검증·완료 웹훅·
receipt·정리를 검사했다. 웹에서는 옵션·업로드·페이지 진행·취소·결과 오류 재시도·페이지 이동·
빈 페이지·다운로드·만료·승인 대기·데스크톱/모바일을 가상 데이터로 검수했다.

고객 실문서의 한국어 폰트·복잡한 표·문서 읽기 순서·최대 크기/페이지 수의 품질·성능·
다른 OS 버전과 실제 플랫폼 등록은 미검증이다. 로컬 검사를 플랫폼 연결 성공으로 해석하지 않는다.
계약은 [연동 지침](SERVICE_INTEGRATION.md) 버전 23의 PDF 절을 따른다.

운영 API·워커를 실행 작업이 없는 상태에서 재시작하고 HTTPS 서비스 목록의 PDF 활성화·
200MB/100페이지/900초, 연동 지침 버전 23, 배포한 웹 번들·워커 연결을 확인했다.
