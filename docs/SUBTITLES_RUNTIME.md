# 영상 자막 실행 기록

기준일: 2026-10-10. 기존 SenseVoiceSmall INT8·Silero VAD·sherpa-onnx STT를 재사용한다.
새 모델·Docker·n8n 워크플로를 추가하지 않는다.

## 실행과 한도

`video.subtitles`를 공통 Job에 등록하고 원본 음성·영상을 업로드한다. 첫 오디오 트랙을
16kHz 모노로 변환해 인식한다. 기존 `STT_ENABLED`, `STT_MAX_DURATION_SECONDS`,
`STT_TIMEOUT_SECONDS`, `STT_CPU_THREADS` 설정과 업로드 한도를 공유한다.
기본 5GiB·음성 길이 1시간·전체 처리 900초·CPU 4스레드다. 무음은 빈 자막으로 성공한다.
오디오 트랙이 없는 영상·원격 플레이리스트는 거부한다.

VAD 구간 텍스트를 문자 수에 비례해 나누어 최대 6초·줄당 42자·최대 2줄의 SRT/VTT를
생성한다. 단어별 정렬이 아닌 **근사 시각**이다. 단어 중간 줄바꿈이 있을 수 있고
실제 발화와 자막 경계가 어긋날 수 있으므로 사용 전 대조가 필요하다.
`video.subtitles` 자체에는 화자 구분·영상에 자막 입히기·번역 자막을 포함하지 않는다.

## 통합 영상 처리의 자막 선택 확장

`video.package.options.subtitles`가 null이면 기존 처리를 유지한다. `mode:sidecar`는
SRT/VTT·전사를 함께 생성하고 `mode:burned`는 같은 자막을 모든 HLS 출력 해상도에 입힌다.
후자는 libass 지원 FFmpeg가 필요하다. macOS에서는 `brew install ffmpeg-full`로 설치할 수
있으며 기존 전역 링크를 바꾸지 않고 `FFMPEG_BINARY`·`FFPROBE_BINARY`를 암호화 env에
설정한다. 실제 경로는 문서에 기록하지 않는다. 변경 후 API·워커를 재시작하고 필터·출력을 확인한다.

원본 첫 오디오 트랙을 한 번 인식하며 같은 Job·공통 연산 슬롯을 유지한다.
영상 재생 시각을 유지하도록 음성 정규화 시 `aresample=async=1:first_pts=0`을 적용한다.
인식 900초와 전체 영상 처리 1800초 제한이 함께 적용된다. 영상 예약에 음성 중간 파일·자막 예약을 더한다.
CPU 인코더 전환 시 자막은 재사용한다. 결과는 `video.zip` 하나이며 별도 `subtitles.zip`은
만들지 않는다. HLS master의 자막 그룹 자동 등록·MP4·사용자 SRT 입력은 포함하지 않는다.
sidecar 웹 미리보기는 같은 출처의 VTT `<track>`을 연결한다. 인식 실패는 전체 실패,
무음은 빈 자막 성공이며 기존 서명 웹훅·receipt·보존 정책을 따른다.

독립 `video.subtitles` 결과는 `transcript.json`, `transcript.txt`, `subtitles.srt`, `subtitles.vtt`,
전체 `subtitles.zip`이다. JSON은 원래 음성 구간 시각을 유지한다. SRT/VTT는 내보낸 자막
시각을 담고 각 4MiB·최대 100,000개 자막으로 제한한다. 입력·중간 파일은 기존 정리를
적용하고, 웹 결과 24시간·플랫폼 결과 receipt 또는 기본 최대 7일 후 삭제한다.
원본·인식 전문을 웹훅이나 로그에 복제하지 않는다.

## 검수

독립 자막 기능 도입 당시 전체 검사 178개 통과·5개 건너뜀(TTS MLX 3·VideoToolbox 2). 합성 음성 영상의 실제
STT→SRT/VTT/ZIP, 무음, 시각·줄 길이·마크업 이스케이프와 기존 STT 제한을 검수했다.
API 서비스·옵션·중복 방지·공통 작업·결과·웹훅·receipt, 가상 데이터 기반 웹 테스트·
오류 재시도·페이지 이동·키보드 스크롤·다운로드·만료·승인 대기·모바일을 검사했다.
실제 사용자 영상의 한국어 띄어쓰기·고유명사·타이밍·최대 입력 성능과 플랫폼의
실제 결과 저장은 미검증이다. 당시 계약은 연동 지침 버전 24를 따랐다.

통합 자막 확장 후 전체 검사 199개 통과·5개 건너뜀·기존 경고 1개를 확인했다.
실제 STT→자막→HLS, 오디오 시작이 2초 늦은 입력, 480p·720p CPU 출력과
인코더 실패 후 CPU 전환 시 자막 재사용을 검사했다. 별도 실행에서는 실제 VideoToolbox
H.264 인코딩으로 두 해상도에 한글 자막이 입혀지고 CPU 전환이 없음을 확인했다.
브라우저에서 통합 작업 등록·재시도·취소·화질 전환·sidecar 자막 켜기/끄기·burned 재생·
다운로드·만료·승인 대기·데스크톱/모바일 화면을 확인했다. 웹 lint·빌드와 백엔드 정적 검사도
통과했다. 운영 API·워커를 재시작하고 HTTPS 서비스 목록·옵션 명세·공개 문서·워커 연결을
확인했으며 운영 Job이나 플랫폼 콜백은 제출하지 않았다. 현재 계약은 연동 지침 버전 28을 따른다.
