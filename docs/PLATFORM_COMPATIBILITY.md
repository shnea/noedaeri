# 플랫폼 파일 처리 기능 대응표

조사일: 2026-10-05. 플랫폼 `main`의 커밋 `f8ea782d766ac6a28fd80480b5bec605eff5e605`를 읽기 전용으로 확인했다. 최초 뇌대리 비교 기준은 `824b9b0`이며, 아래 이미지 항목은 2026-10-05 이미지 통합 처리 구현 결과로 갱신했다. 플랫폼 배포 환경을 실행한 검수가 아닌 소스·테스트 조사 결과다. 플랫폼 저장소는 변경하지 않았다.

목표는 플랫폼이 사용하는 연산을 뇌대리에서 대응한 뒤 플랫폼 전용 호출을 연결하는 것이다. 저장·공개 URL·사용자 파일 권한까지 뇌대리로 옮기는 뜻은 아니다. 원본은 호출 측이 보관하고 결과 묶음에 넣지 않는다.

## 이미지 입력 호환 범위

플랫폼 소스의 이미지 후보는 PNG, JPG/JPEG/JFIF, GIF, WebP, BMP, ICO, TIF/TIFF, HEIC/HEIF, AVIF다. 상한은 32,000,000바이트·40,000,000화소·각 변 10,000px이며 형식과 코덱을 대조한다. GIF·움직이는 입력의 미리보기는 첫 프레임으로 생성하며 애니메이션 보존을 약속하지 않는다.

이 목록은 플랫폼 소스의 허용 목록이다. 실제 배포 FFmpeg가 모든 포맷을 처리한다고 검증된 목록은 아니다. 플랫폼 이미지 테스트는 원본/파생물 분리·미리보기 fallback·권한·Range를 확인하지만 모든 포맷의 실변환 성공 근거는 아니다.

현재 뇌대리 PC에서 확인한 FFmpeg 인코더 목록에는 `libwebp`가 없고, demuxer 목록에도 독립 `heif`·`avif` 항목은 보이지 않는다. 이는 설치된 FFmpeg와 경로에서의 점검이며 모든 디코딩 경로의 불가능을 단정하지 않는다. 이미지 패키지나 별도 네이티브 코덱을 선택하고 실제 샘플로 지원 범위를 검증해야 한다. FFmpeg는 그대로 유지하고 Pillow 12.3.0과 pillow-heif 1.8.0의 네이티브 코덱으로 구현했다. 13개 후보 확장자의 생성 샘플 변환, 방향·투명·ICC·첫 프레임·손상·용량·취소·워커 처리를 검사했다. 실기기 HEIC·HDR·대형 다중 페이지 등은 추가 대조가 필요하다.

## 영상 계약의 구체적 차이

사용자 결정: 뇌대리의 **480p·720p·1080p는 유지**한다. 플랫폼이 이를 수용하도록 변경할 예정이며, 화질 단계의 차이는 뇌대리 수정 대상이나 이관 차단 조건이 아니다. 다른 비트레이트·프로필·파일명 차이까지 자동 승인된 것으로 해석하지 않는다.

| 항목 | 플랫폼 | 현재 뇌대리 |
|---|---|---|
| 기본 화질 | 360 / 720 / 1080 | 480 / 720 / 1080 |
| 영상 비트레이트 | 0.8 / 2.5 / 4.5 Mbps | 1.2 / 2.8 / 5 Mbps |
| maxrate | 목표의 120% | 목표의 100% |
| 음성 | AAC 128kbps·2채널·48kHz 명시 | AAC 128kbps·2채널, 샘플레이트 미지정 |
| 프로필·메타데이터 | H.264 high 명시, metadata 제거 | profile·metadata 정책 미명시 |
| 재생 목록 이름 | `q360.m3u8` 등 | `480p.m3u8` 등 |
| 조각 이름 | `q360-00000.ts` 등 | `480p-00000.ts` 등 |
| master | 독립 조각·FRAME-RATE 명시 | 독립 조각·resolution·bandwidth (FRAME-RATE 태그 미명시) |
| 제한시간 | 해상도별 max(120초, 영상길이×8), 최대 4시간 | 전체 작업 30분 |
| 썸네일 크기 | 2,000,000바이트 이하 | FFmpeg 출력 제한 2,097,152바이트 |
| 입력 전송 한도 | 미리보기 검사와 HLS 검사의 한도가 별도 | 공통 업로드 5GiB (5,368,709,120바이트) |
| 결과 제공 | 플랫폼의 generation 저장과 기존 파일 파생물 | 상대 이름 manifest와 ZIP, 웹 보관 24시간 |

플랫폼은 HLS asset 이름을 정규식으로 제한하고 재생 목록의 상대 이름을 공개 API 경로로 다시 쓴다. 따라서 파일명만 바꾸거나 뇌대리 ZIP을 기존 저장소에 그대로 넣으면 호환된다고 볼 수 없다. 결과 등록 어댑터와 경로 매핑을 연결 단계에서 검증해야 한다.

## 다음 개발 순서

| 순서 | 작업 | 완료 판단 |
|---|---|---|
| 1 | 이미지 통합 처리 — 구현·생성 샘플 검수 완료 | 이미지 검사 → JPEG 썸네일 + WebP 미리보기 + MIME·크기 메타데이터. 원본 미포함. 전체 후보 포맷을 성공/미지원/실패로 검증하고 웹 테스트·지침 제공 |
| 2 | 영상 결과 계약 보완 | 480·720·1080p 유지. 기간·bandwidth·상태 메타데이터를 보완하고 출력 설정·파일명은 플랫폼에서 수용할 계약으로 정리 |
| 3 | 복구와 자원 제한 | 실패 재시도·프로세스 종료 확인·generation 격리·출력 공간 예약·긴 영상 제한시간 검수 |
| 4 | 대응 범위 최종 검수 | 동일 입력의 플랫폼 기준과 뇌대리 결과를 비교. 확대·회전·투명·손상·코덱·무음·세로·큰 파일·취소·재시작 검사 |
| 5 | 플랫폼 전용 API — 구현 | 전용 키·개별 조회·서명 웹훅·제한 재전송·결과 저장 확인·별도 보관 정책. 실제 수신 URL 설정 후 연동 검수 |
| 6 | 플랫폼 쪽 이관 | 플랫폼 저장·등록 어댑터와 기존 뷰어를 연결하고 실제 환경 검수. 뇌대리 기능만 구현됐다고 플랫폼 이관 완료로 보고하지 않음 |

현재 판정: **플랫폼 개발을 시작할 뇌대리 측 API·완료 웹훅·저장 확인 계약을 구현했다. 운영 전환 완료는 아니다.** 전용 키는 암호화 설정으로 생성하고 실제 수신 URL은 플랫폼 준비 후 설정한다. 모의 수신·워커 검수와 실제 플랫폼 파일 등록·뷰어·라우팅 검수는 구분한다. 원본 보기·TXT·Markdown·PDF·오디오 원본 검사/렌더링·OG는 플랫폼에 유지하는 연결 범위로 문서화했다.
